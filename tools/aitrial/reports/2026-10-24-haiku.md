# AI trial 2026-10-24: Claude Haiku 5.5, 30 requests

Setup: app version 0.10.0 (prompt with the BOSL2 thread rule, hints in "Copy for AI", mid-air and
flat-ceiling checks), model `claude-haiku-5-5` as a plain chat, 30 requests (25 English, 5 Swedish),
up to 3 fix rounds. Judge: a slicing-based printability check of every rendered round. Cost $0.32
in all.

## Summary

- **All 30 rendered on the first answer**, without OpenSCAD errors except one (#17, a BOSL2
  argument). 22 were clean at once, 8 needed one or two more rounds, and all 30 ended without
  problems in the app.
- **The fix loop works with this model.** Every round fixed the cause and said why: a 45° brace
  under a hook tip, a support wall under a cantilevered label tab, feet under hinge knuckles, a
  sloped roof over a box cavity. Nothing was faked or removed (unlike a weaker chat model earlier,
  which replaced a thread with straight ridges).
- **The prompt's thread rule works.** All five thread requests used BOSL2 `threaded_rod()` /
  `threaded_nut()` straight away; no `screw_thread()`.
- **The pictures match the requests** for nearly all. Weakest: #12 (a lid with tabs, not a
  print-in-place hinge), #7 (an odd coat hook), #5 (a very plain stand). No check can judge this.

## Found and fixed during the trial

- **False alarm: a floor seen as a flat ceiling** (#19, plant pot). Manifold splits the floor around
  the drainage holes into needle triangles whose facing flips after rounding to float32. Fixed in
  `src/ceilings.ts`: needles only join a ceiling that has real downward triangles. The model now
  passes; a test has the trial's geometry. The false alarm cost a round: the AI could not tell
  what was meant and added a fillet that was not needed.
- After the fix the app and the judge agree on mid-air starts and long bridges in all 40 rendered
  rounds, and still on the 25 real models checked before.

## What the app missed (the judge found it)

| What | Where | Why it matters |
|---|---|---|
| **Too big for the bed** (212 mm on a 180 mm bed) | #24 | The app shows it in the status bar only, not in the problem list or "Copy for AI" – the AI never hears of it. |
| **Overhangs steeper than 45°** | #7, #22 (final answers) | Needs supports or sags. No check in the app. |
| **Thin parts** (thinner than ~0.4 mm, left out by the slicer) | 12 designs, mostly in threads | Needs slicing; mostly harmless fine detail in threads. |

## Other findings

- **The library hint is too vague.** #17's `threaded_nut()` failed an assertion ("the values given
  don't fit together"). The AI could not see which argument it needed (`nutwidth`), gave up the nut
  and cut the thread with `threaded_rod(internal = true)` instead. A hint with the module's
  parameters, read from the bundled library source, would have fixed it in one round.
- **Convert to sketches: code blocks pile up.** #11 (honeycomb holes) became 264 code blocks, #22
  130, #24 85 – one per hole or piece. Threads (#2, #3, #17, #30) and a twisted vase (#9) rightly stay
  code, but hundreds of single blocks are unusable in the feature tree.

## Recommendations, most useful first

1. **Bed size as a problem row** (small): when the model doesn't fit the printer from Settings, a
   row under Model with the size and the bed, so it also reaches "Copy for AI". The prompt could
   add "including the gaps between parts".
2. **Merge code blocks in Convert** (small to medium): neighbouring code features become one block,
   or above a limit the whole model stays one Custom code block.
3. **Overhang check** (medium): faces steeper than 45° reaching out more than ~2 mm, measured on the
   mesh like the other checks and compared with the judge on the same models.
4. **Library hints with parameters** (medium): for an assertion or an unknown argument in a BOSL2 /
   MCAD module, list the module's parameters from the bundled source.
5. **Run the trial again after changes** (`node tools/aitrial/run.mjs`), and try other models.
6. **Thin parts** (large): needs slicing; probably not worth it in the app.
